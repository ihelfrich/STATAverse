A firm-year panel, from merged file to results table

Work through a complete empirical project in Stata: whether firms whose chief executive also chairs the board, firms that turn their assets over faster, and firms with positive operating cash flow pay their auditor more in non-audit fees. Twelve steps take a merged file to a table of five models.

New to do-files? Begin with a reproducible do-file in guided practice →

How to use this lab

Each step explains one decision and gives you Stata lines with blanks (____) to complete. Run executes them in a Stata session that carries over from step to step, prints the output as Stata prints it, and checks the result in the data itself, not your typing. Run starts its step afresh every time, so a line that failed can be corrected and run again. The command line under the results is for looking around at any point: tab, summarize, list in 1/10, count if.

Data

Simulated firm-year panel: invented firms, fiscal years 2004 to 2023.

A file you open is read by this page, on this computer. It is not uploaded anywhere, and nothing of it is kept once you close the tab. .dta and .csv files are accepted.

In Stata, import delimited reads the downloaded CSV with fiscal_ye as a number and datadate as text. The do-file you take away from the lab lists the lines that load it as the lab holds it.

The columns this lab expects

The steps are written for a merged firm-year file with these column names. If your file has them, the lab runs on it as it stands. Columns marked optional can be absent; the step that reads them says so.

          What this lab does not cover, and where it differs from Stata
        
        
        
          
          
        • 
            The commands run in an interpreter written for this site, not in
            Stata. The worked version of every step was run in Stata 19 and here
            on the simulated panel, and the printed output and the estimates
            agree. Lines you write yourself have not been compared in that way.
            After a logit in which some industries predict the outcome
            perfectly, margins, atmeans can give an estimate where
            Stata reports that it is not estimable.
          
          • 
          
        • 
            Community commands that are not part of Stata are not available:
            winsor2, reghdfe, ppmlhdfe,
            esttab, outreg2. The steps use what Stata
            ships with: a _pctile loop, areg,
            poisson and estimates table.
          
          • 
          
        • 
            areg absorbs one variable here.
            margins has no post option, and
            estimates table lacks a few of Stata's display options.
            regress with a dummy for each of several thousand firms
            takes minutes; absorb the firm instead.
          
          • 
          
        • 
            regexm(), regexr() and
            regexs() read a pattern as Stata 18 and 19 do when no
            version is set: \s, \d,
            \b, {4} and [[:space:]] work,
            on the bytes of the text. After version 17 they read it
            as older Stata did. A few constructs that the browser cannot read
            the same way (possessive or atomic groups, \p{}, a flag
            set partway through a pattern) stop with a message rather than give
            a different answer. A group such as
            i.(industry2 fyear) works in a list of regressors, but
            not inside an interaction.
          
          • 
          
        • 
            Run puts the data back to the start of its step before it runs. In
            Stata a second generate of a variable that exists stops
            with already defined; there you would run the do-file
            again from the top.
          
          • 
          
        • 
            The checks read your session: which variables exist, where they are
            missing, which rows a model used, how it was fitted. They do not
            compare your numbers with stored answers, so they also work on your
            own file, and a step that passes is built correctly without being
            the right specification for every question.
          
          • 
          
        • 
            A CSV file loses types, as it does in Stata's
            import delimited: leading zeros go, and dates arrive as
            text. The lab adds the lines that repair the year-end columns and
            shows them to you. A .dta file keeps its types.
          
          • 
          
        • 
            The simulated panel is built in this page from a fixed seed. Its
            firms are invented and its results say nothing about real companies.
            The lab does not cover the two merges that produce such a file (the
            merge and reshape lab does), instrumental
            variables, or the choice between fixed and random effects.
