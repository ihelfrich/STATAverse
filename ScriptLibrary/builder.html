Project folder

The project folder is Stata’s working directory. Relative paths in the do-file start here.

Finding a path on Mac

  1. Open the project folder in Finder.
  2. Choose View → Show Path Bar.
  3. Control-click the folder in the path bar and choose Copy as Pathname. Paste the path below.
Apple’s Finder instructions

Finding a path on Windows

  1. Find the project folder in File Explorer.
  2. Hold Shift and right-click the folder, then choose Copy as path. In Windows 11, it may appear in the first context menu.
  3. Paste the path below. Surrounding double quotes are removed, and backslashes are converted to forward slashes for Stata.

Alternatively, open the folder, click the address bar to reveal its full path, then copy it.

Use an existing folder. Paths are saved in this browser with the plan; the website cannot check whether a folder exists on your computer.

Data and output folders

A simple arrangement keeps the original data in a data folder, do-files in a code folder and results in an output folder, all inside the project. Create those folders in Finder or File Explorer if you use this arrangement. 

course-project/
  data/    survey.csv
  code/    analysis.do
  output/

The builder also accepts full paths when files are stored elsewhere. A browser file chooser does not disclose the full local path; copy it from Finder or File Explorer.

Data file

Choose the format and enter the file’s location. The generated import command reads it when the do-file runs in Stata.

Enter a path relative to the project folder, such as data/survey.csv, or paste the full file path. Include its extension.

Stata uses the first worksheet when this field is blank.

Column numbers start at 1. Keep identifiers with leading zeros as text. Other columns use Stata’s type detection.

Checking variable names after import

The do-file includes describe and count immediately after import. Stata can change headings that contain spaces or punctuation. Use the names printed by describe in the next stages.

When the names are unfamiliar, choose Summary statistics with no variable list. Run that first do-file, inspect the names, then return to add preparation and analysis.

Data preparation

Add the operations the analysis needs, in the order they should run. Each step refers to the variable names available at that point.

No preparation steps. Continue if the data are already ready for analysis.

Filters exclude missing values explicitly. Logarithms stop on nonpositive values so an invalid transformation cannot silently change the sample. Original files are not modified.

Analysis specification

Select the analysis and assign variable roles. The choices here determine syntax; the research question and design determine whether the specification is appropriate.

The identifier–time pair must uniquely identify observations. Time must be numeric and coded in Stata’s time units; convert text dates before declaring the panel.

Robust standard errors address variance misspecification under independent observations. Use clustering when observations are dependent within sampling or treatment groups.

For identification assumptions and alternative specifications, see Method comparison.

Output and review

A single dot uses the project folder. Use output for an existing subfolder, or paste a full folder path.

For example, assignment1 produces assignment1.do, a log when selected, and model or graph files for the selected analysis.

Running the do-file in Stata

  1. Download the .do file. Open it in Stata’s Do-file Editor.
  2. Check the paths and variable names. Save any data currently held in Stata before running: the import replaces the data in memory.
  3. Run the whole file using the editor’s Do action. The local path definitions must run with the commands that use them.
  4. If Stata stops, read the first error. Confirm the file location with Finder or File Explorer, and use describe to check variable names and types.

Code is assembled entirely in this browser. These do-files target installed Stata 16 or later; the browser practice engine supports a smaller command set.
