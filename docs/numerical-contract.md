# Browser numerical contract

The practice workspace is an educational subset of Stata. It is not Stata, and finite numerical agreement does not establish general language or estimator equivalence.

## Data and expressions

Rows are observations; column metadata identifies numeric and string variables. JavaScript numbers store numeric values in double precision. `null` represents ordinary Stata numeric missing (`.`), which compares above finite numbers. Empty strings represent string missing. Extended missing values are rejected. Arithmetic with numeric missing propagates missing; domain errors return missing. Input types are checked. A failed command restores its pre-command state.

Summaries and correlations rescale inputs to avoid ordinary intermediate overflow. Graphs and regressions reject absolute input values above 1e100; regression also rejects nonfinite computed coefficients or covariance. This is an explicit educational-environment limit, not a claim about native Stata's range. A session permits 500 successful commands and 100 variables. String values and literals are limited to 10,000 UTF-16 code units; the working dataset permits two million code units across string values and labels. Concatenation checks its proposed length before allocating the result. A failed transformation restores the preceding data and model. Successful command history is bounded at one million code units, matching saved-work validation.

Undo retains at most 50 states within estimated budgets of 750,000 cells and 32 MB; Results retains at most 200 entries within 500,000 cells and 16 MB; command receipts retain at most 500 entries within 8 MB. Each retains at least its most recent item. The byte estimate counts two bytes per string code unit, values, keys, array slots and object overhead. These are structural retention budgets, not measurements or guarantees of total browser heap usage. Changed-cell receipts show at most 200 edits and shorten string previews after 160 code units, with an explicit notice; dataset values remain intact. Exported do-files retain the successful command history even when older displayed results have been released. If an older saved command exceeds a new bound, replay stops and disables subsequent saves so the original stored history remains available for backup.

The expression parser never uses JavaScript `eval` or `Function`. Variables resolve against an explicit column list. Ordinary arithmetic, comparisons, logical operators and named functions form the supported grammar. The executed native Stata scalar fixture catches language differences: powers associate left to right; `inrange()` treats a missing bound as open, but a missing tested value as false. These differed in the initial implementation and were corrected with regression tests.

## Do-file programming

Each Run action creates a fresh local-macro scope. `local name text` stores text; `local name = expression` evaluates a scalar expression. Backtick/apostrophe substitution supports nested macro names and undefined locals substitute empty text. The implementation rejects global references, escaped references, compound macro quotes and extended macro functions. It does not reinterpret substituted text as JavaScript. Numeric local formatting is checked on finite examples, not certified for every magnitude or format.

`foreach` supports `in`, `of local` and `of varlist`. Varlists preserve repeated names. `forvalues` supports integer start/end, explicit steps and alternate second-value notation. Loop index locals are removed after completion, including pre-existing values of the same name. Other locals defined inside the body survive until the current Run action ends. Nested `if`/`else` blocks evaluate one numeric condition; variable references use the first observation. Ordinary numeric missing counts as true. Single-line programming if and else-if are not implemented.

A run accepts 50,000 source characters, 200 logical lines, 32 nested blocks and 1,000 operations; the independent 500-command session bound also applies. Structure is parsed before executing any command. A runtime error stops later execution while preserving earlier successful commands; a failing data command rolls back only itself. A cursor inside a control block executes its enclosing outer block. Explicit selection executes exactly the selected text in a fresh local scope. Locals defined outside that selection are unavailable.

Successful expanded commands enter replay and analysis exports. The current original source is retained in the editor draft and complete project ZIP. Results retain the original and expanded command when they differ. Full-result and lightweight-receipt budgets apply during execution, so repeated tables cannot accumulate unbounded output before rendering. Local definitions themselves do not create data snapshots or enter the expanded history. A purely empty loop or unchosen conditional produces an explicit control receipt rather than an empty-editor message.

`tools/check-program-native.mjs` records 14 constructed comparisons at relative tolerance 1e-14 and one explicit empty-sample boundary in `docs/verification/program-native.json`. Reading a data variable in a control expression with no observations returns r(2000) here; `_N` remains usable. The installed executable returned a retained prior first-row value in that case, which is not adopted as a portable specification. The executable's unmodified licensed vendor provenance has not been established. These checks support the recorded cases, not universal Stata compatibility.

## Ordinary least squares

For the complete-case sample, the design matrix contains the listed predictors followed by an intercept. `n` is the sample size, `k` the number of estimated coefficients, and residual degrees of freedom are `n-k`. An intercept is always present. Plain variable lists retain their existing rejection of constant/collinear predictors and models without positive residual degrees of freedom. Factor specifications select independent columns as described below.

Predictors are centered and scaled. `ml-matrix` QR solves the least-squares problem on that scale. A linear transformation maps coefficients and covariance back to the original units. The inverse of the QR upper-triangular factor supplies the covariance bread without forming unscaled normal equations. A singular-value check rejects ill-conditioned standardized designs above a condition-number threshold of 1e10.

Conventional covariance is `SSE/(n-k) × (X'X)^-1`. Robust covariance is HC1: `n/(n-k) × bread × sum(x_i x_i' e_i²) × bread`. Student-t inference uses `n-k` degrees of freedom. Coefficients, standard errors, t statistics, two-sided p-values and 95% intervals are displayed; no unsupported F statistic is fabricated.

Fitted values use the observed predictors even for observations outside the estimation sample. Residuals also require an observed outcome. Browser data-changing commands clear the fitted model; this deliberate simplification is stated in the interface.

### Factor variables and interactions

Regression supports `i.`, `c.`, `#`, `##`, numeric level selectors such as `2.group`, `ibN.`/`bN.`, `ib(first).`, `ib(last).`, `ib(freq).`, `ibn.`, and grouped lists such as `i.group##c.(x z)`. Bare variables inside an interaction are categorical, as in Stata; plain variables elsewhere are continuous. Categories must be nonnegative integers. Numeric source variables are validated before fitting. The expansion uses levels in the complete-case estimation sample. Source columns remain unchanged; fitted model terms contain serializable component metadata for prediction, worker transfer and replay.

The expansion is bounded at 256 columns, eight factors per interaction and 500,000 design cells. Reference terms are separated from fitted terms. Twice-reorthogonalized modified Gram–Schmidt identifies redundant columns at relative residual norm below 1e-12, preferring nonreference columns within each term. The retained design still passes the existing SVD conditioning check and QR fit. Empty and redundant columns are disclosed. Selected native fixtures establish the coefficient parameterization for those cases, not every rank-deficient design. Saturated factor fits display coefficients and predictions with residual df zero; covariance, standard errors, tests, confidence limits and RMSE are unavailable, rather than fabricated from a zero denominator.

`tools/check-factor-native.mjs` independently executes 69 fits, including the reported `reg hours attendance##score` and `reg hours c.attendance##c.score`, conventional and HC1 inference, categorical cell indicators, group-specific slopes, three-way interactions, powers, custom/absent reference categories, grouped lists, missing values and qualifiers. Numerical fixtures compare coefficients by term name, full retained covariance, N, residual df, SSE, R-squared and all-observation predictions/residuals at 2e-8 relative/unit-absolute tolerance. Native logs remain outside the project. Browser tests cover worker and cooperative execution, interpretation, reload, undo and exported do-files. `fvset`, omitted-level operators, arbitrary level ranges and time-series operators remain unsupported.

Semantics reference: [Stata User's Guide, section 11.4.3](https://www.stata.com/manuals/u11.pdf). Practice and its worker now import one content-hashed shared interpreter chunk, included in the offline cache; the 600,000-byte gzip offline-core gate is unchanged.

## Regression analysis lab

The separate `Labs/` experience generates independent standard-normal z, u and ε using a seeded Mulberry32 uniform generator and a Box–Muller transform. It constructs x = ρz + √(1 − ρ²)u and y = 2 + βx + γz + σε. Parameters are bounded explicitly: 20–1,000 observations, |ρ| ≤ .95, |β| and |γ| ≤ 5, and .1 ≤ σ ≤ 5. The default seed is an illustrative draw, not a claim that estimates equal their population values. CSV export preserves the actual observations; a Stata seed alone will not reproduce the browser generator.

Full and short regressions use an identical sample. Partial regression removes z and an intercept from both x and y. The residual cross-product ratio recovers the full-model x coefficient. Displayed inference comes from the full model and its n − 3 residual degrees of freedom; the standalone residual regression's default standard error is not substituted. The finite-sample omitted-variable decomposition uses the fitted z coefficient and the slope of z on x, while the separate population short slope is β + γρ.

Leverage is the full-model hat diagonal. Standardized residuals divide residuals by s√(1 − h), and Cook's distance is h·e²/[k·s²·(1 − h)²], with k = 3 and s² = SSE/(n − k). These classical diagnostics use conventional residual variance even when the displayed covariance uses HC1. The one-observation comparison refits the model without that row, but leaves the experiment's data intact. A manual offset changes one generated row and is recorded in the exported metadata and do-file.

`tools/lab-reference.R` independently checks four synthetic cases using R `lm`, `sandwich::vcovHC`, `hatvalues`, `cooks.distance` and `rstandard`. Coefficients, standard errors, partial-regression values and diagnostics are checked to 1e-10 relative/unit absolute tolerance; confidence limits use 1e-6. `tools/check-lab-native.mjs` executes the exported Stata commands with native double input substituted for CSV import, and asserts coefficient, standard-error and all-observation diagnostic differences below 1e-9. Cases include strong collinearity, a sign reversal, HC1 covariance and a modified point. These are bounded checks, not evidence of universal equivalence or empirical causal identification.

## Group statistics and observational units

Browser `egen` supports mean, sample SD, minimum, maximum, median, nonmissing count and total of one source variable, optionally within `by(varlist)`. It also supports numeric `rowmean`, `rowtotal`, `rowmiss` and `rownonmiss` across source variables. The source grammar accepts variables rather than general expressions; explicit storage can only be double. Row functions do not accept `by()`. `count()` accepts numeric or string input, excluding numeric missing or empty strings. Missing grouping keys form groups. Qualifiers restrict both calculation and assignment; excluded observations receive numeric missing in the new column. Existing rows and ordering remain intact.

`collapse` supports the same statistics, using `sum` rather than `total`, default mean, distinct renamed outputs and numeric sources. Without `cw`, each statistic uses its own nonmissing sample. With `cw`, rows missing any source variable are removed before grouping; groups with no complete cases disappear. An empty eligible sample fails atomically with r(2000). A total defaults to zero if all source values are missing; `egen total()` and `rowtotal()` accept `missing` to leave such a total missing. SD requires at least two nonmissing values. The interface reports each nonmissing count, changes the displayed observational unit after collapse and restores that metadata with the data.

Results retain read-only previews of up to fifty selected source rows per group at their command-time positions. Later mutations cannot alter them. All eligible rows enter calculations, and partial previews are identified. Group tables display at most two hundred groups; the working data and retained-results export include all groups. Text previews are shortened explicitly, and retention budgets include these snapshots. Unicode key ordering follows browser string comparison and has not been certified against every native collation; extended missing values are unsupported.

`tools/check-grouped-native.mjs` records twenty-five native cases using explicit double input, without Java-dependent import. Cases cover every implemented group/row function, selected and empty samples, string counts, missing keys, singleton/all-missing groups and variablewise/casewise collapse. Comparisons require numeric agreement within 1e-10 relative/unit absolute tolerance and exact missingness. Weights, by prefixes and additional functions remain unsupported. Finite fixtures do not establish complete language equivalence.

## Inference and repeated-sampling lab

The separate inference lab uses balanced independent groups. Its generator is x_gi = √ρₓ a_g + √(1 − ρₓ)v_gi and y_gi = 2 + βx_gi + σs(x_gi)[√ρₑ b_g + √(1 − ρₑ)ε_gi], with independent standard-normal latent variables and s(x) = exp(hx/2 − h²/4). The scale normalization gives E[s(x)²] = 1. The error correlation ρₑ is conditional on the complete predictor realization; with varying scales, unconditional correlation need not equal it. Exogeneity is imposed by construction. No identification claim about an empirical dataset follows.

Bounds are 5–100 groups, 2–50 rows per group (at most 5,000 observations), 50–2,000 repetitions, β and the null coefficient in [−5,5], σ in [.1,5], h in [0,1.5], correlations in [0,.95], and confidence levels 90%, 95% or 99%. Browser sample r uses Mulberry32 seed `(seed + imul(r, 0x9e3779b9)) >>> 0`, with r starting at zero, and Box–Muller normals. All methods use the same observations in each repetition. Fixed-seed parameter comparisons retain latent draws. Browser/Node transcendental functions can differ by a last binary digit; cross-runtime checks use numerical tolerance. Exact browser observations are exported for native comparison.

With d_i = x_i − x̄, Sxx = Σd_i² and OLS residual e_i, the slope variance estimates are SSE/[(N−2)Sxx] (conventional), [N/(N−2)]Σ(d_i e_i)²/Sxx² (HC1), and [G/(G−1)][(N−1)/(N−2)]Σ_g[Σ_i∈g d_i e_i]²/Sxx² (CR1). Intervals use Student-t critical values with N−2 or G−1 degrees of freedom, respectively. Two-sided p-values test the selected null coefficient. Covariance choice leaves the coefficient unchanged. Singleton clusters nest HC1 covariance but not its reference degrees of freedom.

Coverage and rejection are recorded from the full-precision intervals. Repetition summaries report counts, rates, mean SE/width, empirical coefficient standard deviation, estimated bias and Monte Carlo SE of the mean. Rate uncertainty uses 95% Wilson intervals, including at observed rates zero or one; each method's interval concerns its own rate, not a paired difference between methods. The display identifies rejection as false positives when the null equals β, and as power otherwise. Increasing repetitions reduces simulation uncertainty rather than increasing a regression's sample size.

Runs execute in a dedicated worker, terminated on cancellation or page exit. Parameters are fixed during a run. A generation identifier prevents stale worker results from replacing a later run. Incomplete runs are excluded from exports. Completed results are held in memory rather than silently persisted. Sixty interval lines appear at once; all repetitions enter the summaries and export. The horizontal plot scale is shared across methods within a displayed window.

Five independent R cases check coefficients/covariance/residuals to 1e-10 relative/unit absolute tolerance, confidence endpoints/critical values to 1e-6, and p-values to 1e-7. Native Stata checks the same five samples under all three covariance choices. Three directly executed native programs additionally run 50 repetitions each and check returned quantities, interval centers and decision consistency. Native simulation specifies `mt64`, maps the browser seed to 1–2,147,483,646, and stores returned results through `saving(..., double replace)`; native draws are not browser draws. A 200,000-observation seeded moment check separately probes generator means, variance, exogeneity and within-group latent dependence with .03 absolute bounds. These finite checks do not establish universal statistical accuracy or ideal small-group coverage.

## Merge and reshape lab

The separate synthetic-data lab supports `merge 1:1`, `m:1` and `1:m`. Keys must exist with compatible types in both sources, and the declared unique sides are checked before filtering. Ordinary numeric missing and empty-string keys match identical key tuples. This behavior does not establish a real-world identity. Master-only and using-only rows retain missing values for fields available solely from the absent source. The default keeps overlapping non-key master values, including missing values. `update` fills missing master values; `update replace` also replaces conflicting observed values. Missing using values never replace observed master values. A conflict receives code 5 even if another field was filled; otherwise a fill receives code 4. Retaining matched observations includes codes 3, 4 and 5. Category counts describe the full merge before the retention rule; excluded rows are reported separately.

Reshape supports positive integer suffixes/indexes from 1 through 999. Wide identifiers must be unique; long identifier/index tuples must be unique. Nonstub variables must be constant within identifiers before reshaping wide. Wide-to-long uses the union of selected stub-family suffixes; absent family columns produce missing cells. Long-to-wide uses the union of index values; absent identifier/index records also produce missing cells. An existing missing source value is distinct from a structurally absent source cell in the trace. Wide columns outside selected families remain repeated columns in long data. String stubs can be reshaped wide. Full remembered-reshape, string-index and `@` syntax are unsupported.

Each result records source positions and cell origins without mutating either input. Positions refer to the supplied table before the operation. Display order is canonical by key in the browser and may differ from native Stata order. Unicode collation and extended missing values are not certified. Input and output bounds are 10,000 rows, 100 variables, 200,000 cells, 10,000 characters per field and 2,000,000 text characters. Invalid operations remove the prior result from the current display and disable export. An empty retained result is valid and can be exported.

Project exports contain original synthetic source CSVs, the result, options and a do-file with explicit import typing. Native verification replaces only Java-backed CSV import with explicit data setup and executes the remaining exported operation and export commands. Thirty-two finite integer/string cases agree exactly on canonical row values and missingness, including composite and missing keys, empty retained samples, empty master data, duplicate/type errors, overlap decisions and both reshape directions. ## Error capture and output prefixes

`capture`, `quietly` and `noisily` accept individual commands and brace blocks, including nested blocks and prefixed supported loops/conditions. Prefix abbreviations require at least three characters; optional colons are accepted. The last output prefix controls visibility. `quietly` suppresses ordinary output but does not catch errors. `capture` suppresses output, catches command errors and sets `_rc`; `capture noisily` retains output. Successful ordinary commands leave the last captured code unchanged. An outer capture of a successful inner capture returns zero. `_rc` is an expression scalar, never a text replacement inside quoted strings.

Within a captured brace block, an error skips the rest of that block, preserves earlier successful changes and continues after its closing brace. A failed individual command remains atomic. The installed runtime gives a direct `capture foreach` or `capture forvalues` a zero return code after stopping at a body error; wrapping the loop in `capture { ... }` instead retains the error code. The browser reproduces these tested forms. `confirm` checks existing, numeric, string or new variable names without changing data. `exit 0` ends the current Run without clearing data, even inside capture. Nonzero `exit` and `error` raise catchable return codes. User-defined programs, single-line programming `if`, arbitrary file checks and other `confirm` variants remain unsupported.

Saved history records captured failures as well as successful commands. Prefixed blocks compile their executed path into a brace block with local substitutions resolved, preserving capture scope and `_rc` during reload and export. Undo restores the entire prefixed block, including data, model and preceding return code. A compiled block must itself fit the existing 200-command/50,000-character parser bounds; otherwise the block's changes are rolled back. History also retains lightweight receipts for suppressed output and captured errors. Worker protocol version 2 includes return-code state; stale protocol results are rejected.

The 39 cases in `verification/prefix-native.json` compare return codes, dataset columns/values, quiet/noisy output sentinels and browser-history replay against the installed native executable. These finite cases do not certify arbitrary nesting or complete Stata behavior, and the installed binary's provenance is not certified. Browser resource errors (`r(901)`), cancellation and malformed structural input cannot be swallowed by capture. Unit and browser checks separately cover these limits, worker/fallback equivalence, grouped undo and exported history.

## Functions, subscripts and the by prefix

Added 9 November 2026 as the first increment of [the runtime expansion](runtime-and-courses-spec.md). These are additions to the existing interpreter. No existing command changed its results, so saved sessions replay as before.

Expressions accept `cond`, `max`, `min`, `int`, `trunc`, `floor`, `ceil`, `sign`, `mod`, `log10`, `strlen`, `strupper`, `strlower`, `strtrim`, `strltrim`, `strrtrim`, `stritrim`, `substr`, `strpos`, `subinstr` and `real`, with the older names `length`, `upper`, `lower`, `trim`, `ltrim`, `rtrim` and `itrim`. Behavior that students tend to guess wrong was taken from installed Stata and is fixed by test: a missing test in three-argument `cond()` selects the first value; `max()` and `min()` skip missing arguments; `mod(x, y)` is missing for a zero or negative `y`; `strpos(s, "")` is 1; `stritrim()` collapses blanks only between nonblank characters; `substr()` truncates fractional arguments and returns an empty string for a start of zero, a start beyond the text or a length below one. Stata's string functions count bytes. `strlen`, `substr` and `strpos` therefore stop with an explanation on text outside ASCII; they never return a character position that Stata would not. `string()`, regular expressions, the `ustr` family, date functions and random-number functions are not implemented.

`x[k]` reads variable `x` in observation `k`; a position outside 1 to `_N` gives missing. Subscripts work in `generate`, `replace` and `if` conditions. `generate` and `replace` now test the condition and store the value one observation at a time, as Stata does, so `replace x = x[_n-1] if missing(x)` carries values forward. For expressions without subscripts this ordering cannot change a result. `assert` does not accept subscripts.

`by varlist [(varlist)] [, sort]:` and `bysort` (`bys`) run `generate`, `replace` and `egen` within groups, with `_n`, `_N` and subscripts counted inside each group. `summarize` and `count` under `by` report every group, including one with no selected observations, in a single table where Stata prints one table per group. `bysort` with a reporting command still reorders the data, as it does in Stata. Other commands under `by` stop with return code 198. `in` with `by` returns 190. The data carry a record of the variables they were last sorted by. Plain `by` requires that record to begin with its variables and returns code 5 otherwise. `sort` and `bysort` set the record. `replace` of a sort variable shortens it to the variables before that one, and dropping a sort variable does the same. `generate`, `egen`, `label` and observation deletions keep it. Every other data-changing command clears it, which is sometimes stricter than Stata: the student is asked to sort again, and no result is produced from an order that might be wrong.

Two differences from Stata are deliberate. Stata orders tied observations arbitrarily on `sort`; the browser keeps their previous relative order, so a result that depends on the order of ties is reproducible here and not in Stata. Stata sorts the data before rejecting `bysort ...: command in ...`; the browser undoes a failed command completely, including that sort.

`tools/check-functions-native.mjs` ran 75 scalar expressions, 23 data sequences and 4 grouped reports in installed Stata and wrote `tests/fixtures/stata-functions.json`. `tests/functions.test.mjs` compares every case with the interpreter: values, variable lists and return codes agree, with row order left uncompared in the two cases described above. ## New runtime: command grammar and storage types

This section describes `src/runtime/`, the new runtime specified in [the runtime and courses spec](runtime-and-courses-spec.md). No page loads it yet. The existing interpreter and everything above are unchanged.

**Grammar.** A command declares what it accepts in the notation of Stata's own `syntax` command, and `applySyntax` in `src/runtime/syntax.js` checks a command line against the declaration. It handles a varlist with abbreviations, the wildcards `*`, `?` and `~`, ranges and `_all`; new variables with a storage type; name lists and free text; `if`, `in`, `using`, `=exp` and weights in any order; and options that are flags, `no` flags, integers, reals, strings, names, variable lists, number lists, confidence levels or passed through, each with its minimum abbreviation, plus `*`. It returns the locals `syntax` would set and the same information in typed form. Errors carry Stata's return codes.

**Values and storage.** Numeric values are JavaScript doubles. The 27 missing values are the doubles Stata uses for them (system missing is 2^1023, then `.a` to `.z` in steps of 2^1011), so ordinary comparison gives Stata's ordering and `x > 100` is true for a missing `x`. `byte`, `int`, `long`, `float` and `double` have Stata's ranges. A value outside an integer type's range becomes missing under `generate`, a fraction is truncated toward zero, and `float` holds single precision, so a `float` 0.1 does not equal the literal 0.1. `replace` widens storage as Stata does: integer types step up to `int`, `long` and `double` for larger integers; a fraction moves `byte` and `int` to `float` and `long` to `double`; `float` and `double` never change, and a value too large for `float` becomes missing. Strings are measured in bytes of UTF-8, default to the width of the longest value, widen on `replace` and never narrow. `recast` refuses a change that would alter any value unless forced. Display formats follow the type at creation and do not change when the type does.

**Sort order.** Sorting is stable and puts missing values last in their own order. A descending key puts numbers in descending order and then missing values. The dataset records the leading ascending keys as its sort order. Replacing or dropping a key leaves the data sorted on the keys before it; adding observations, dropping observations, reordering variables, recasting and creating variables keep the record; renaming a key renames it in the record. Dropping the last variable leaves no observations.

**Evidence.** `tools/check-runtime-native.mjs` ran 170 command lines through seven `syntax` declarations and 70 storage sequences in installed Stata under `version 17` and wrote `tests/fixtures/stata-runtime.json`. Numeric values were written with `%21x` and are compared exactly. `tests/runtime-syntax.test.mjs` and `tests/runtime-store.test.mjs` compare return codes, every local, storage types, values, the number of observations and the recorded sort order.

**Limits of that evidence.**

- Three of the 170 lines are not compared. Stata's `syntax` compiles `if` and `=exp` and so rejects a missing variable or a string where a number is required. The grammar passes each expression to a hook for the runtime's expression compiler, which does not exist yet.
- Stata leaves a trailing blank in the `if` and `exp` locals when another clause follows; the comparison ignores trailing blanks.
- For reserved or malformed variable names the store is checked for refusing the same names as Stata, not for the same return code, because the code depends on how `generate` reads its arguments.
- Stata's `sort` orders ties arbitrarily. The store's sort is stable, and the cases use keys without ties.
- A string cut to a byte width is cut at a character boundary. Stata cuts at the byte.
- Factor-variable and time-series operators in a varlist are refused with return code 101.

## New runtime: expressions, formats, sessions and commands

These parts of `src/runtime/` were added on 10 November 2026. The only page that loads them is the unlinked preview at `Console/`. Each paragraph names what is implemented; the evidence and its limits follow.

**Expressions** (`expression.js`, `functions.js`, `distributions.js`). Stata's precedence as Stata applies it, which is not quite as its manual lists it: `^` binds tighter than the prefix operators `!` and `-`, so `!a^b` is `!(a^b)`; `!` may not be followed directly by a sign; and the comparisons are each at their own level in the order `!=`, `>`, `<`, `<=`, `>=`, `==`, so `a == b < c` is `a == (b < c)`. These were found by running 400 machine-written expressions in Stata. Machine-written string expressions and do-files found nine more differences, all now corrected: an `if` inside a block could decide whether that block's `else` ran; `local n++` stores the text `++` and only the prefix forms increment; `++` may not appear in an expression; `word count` of nothing is 0; a `replace` that changes no value leaves the sort order recorded, `strpos()` finds nothing in an empty string, `strreverse()` reverses bytes, `by` runs nothing when there are no observations, and `compress` leaves types alone then. Two further rules show up in rounding: division binds tighter than multiplication and subtraction tighter than addition, and a power is computed exactly only for a whole nonnegative exponent and as exp(y ln x) otherwise, so `10^-2` is not 0.01. Any arithmetic on a missing value gives system missing; `floor`, `ceil`, `round`, `int`, `float`, `clip`, `cond`, `real` and subscripts pass an extended missing value through. Subscripts, `_n` and `_N` are relative to the by-group, `sum()` restarts with each group, and `L.`, `F.` and `D.` work after `xtset` or `tsset`. About 130 functions: numeric, string (byte-based, with the `u` forms on characters), date, and the normal, t, F and chi-squared distributions with their inverses.

**Display formats** (`format.js`). `%g`, `%f` and `%e` with the `-`, `0` and `c` modifiers, string formats, and the date formats `%td`, `%tm`, `%tq`, `%tw`, `%th` and `%ty` with custom codes. `%f` rounds the exact binary value and sends an exact tie to the even digit; `%g` and `%e` send it up.

**Sessions** (`session.js`, `dofile.js`, `macros.js`). Comments, continuation lines and `#delimit`; local and global macros with nesting, `=exp`, extended functions and increments; `foreach`, `forvalues`, `while`, `if` and `else`; `program define` with `args`, `syntax` and `return`; `capture`, `quietly`, `noisily`, `by` and `bysort`. A loop's macro does not outlive the loop, and `forvalues i = 5/1` runs no iterations.

**Commands.** Data: `generate`, `replace`, `egen`, `collapse`, `drop`, `keep`, `sort`, `gsort`, `rename`, `order`, `recast`, `compress`, `label`, `format`, `preserve`, `restore`, `expand`, `xtile`, `duplicates`, `destring`, `tostring`, `encode`, `decode`, `recode`, `input`. Files: `save`, `use`, `append`, `merge` (1:1, m:1, 1:m) and `reshape`, on a folder that lives in the session. Reports: `count`, `summarize`, `tabulate`, `list`, `describe`, `tabstat`, `correlate`, `ttest`, `codebook`, `levelsof`, `ds`. Graphs: `scatter`, `line`, `histogram`, `twoway`. Estimation: `regress` (robust, clustered), `logit`, `probit`, `poisson`, all with factor variables and interactions written with `i.`, `c.`, `#` and `##`, `ivregress 2sls`, `xtreg` (`fe`, `re`), with `predict`, `test`, `lincom`, `margins`, `marginsplot`, `estat ic`, `estat vif`, `estat gof`, `estat classification` and `estimates store`, `restore` and `dir`. Several of these agree with Stata only because the runtime repeats arithmetic that Stata's own programs happen to use. `estat ovtest` rescales the fitted values to [0, 1] and stores their powers in single precision; `estat imtest` keeps its residuals, cross products and moment terms in single precision; `kwallis` keeps a running total in single precision. Computed in double precision throughout, each statistic differs from Stata's in about the seventh digit. `estat imtest` also runs `compress` on the data in Stata, which changes storage types as a side effect, and the runtime does the same. `ivregress, first` prints the first stage at 95 percent whatever `level()` says, as Stata does.

**Further estimators, added 10 November 2026.** `tobit` with `ll()` and `ul()`, `ologit`, `oprobit`, `mlogit` and `nbreg` are fitted by one maximum-likelihood routine that takes Newton steps on an analytic gradient, with the Hessian found by differencing that gradient. Their printed tables agree with Stata's to the sixth or seventh digit and their `e()` scalars to 1 part in 10^5, the tolerance already used for `logit`: Stata stops iterating at a tolerance, so the two programs end a hair apart, and which is nearer the maximum is not established. Iteration logs follow a different path and are not compared. `qreg` minimises the sum of weighted absolute deviations exactly; its coefficients, sparsity, bandwidth and standard errors agree with Stata's to 1 part in 10^9, and a unit test checks the solver against an exhaustive search on 60 small problems with tied values. Stata's `qreg` bandwidth, and so its standard errors, depend on `level()`, which the runtime follows. `newey`, `xtreg, be`, `nlcom`, `testnl` and `hausman` agree to 1 part in 10^9; `nlcom` and `testnl` differentiate numerically.

After `mlogit`, `predict`, `test` and `lincom` are refused; after `ologit` and `oprobit`, `predict` gives only the linear prediction. `tobit`, `nbreg`, `mlogit` and the ordered models take conventional standard errors only. `newey` refuses a panel and a time variable with gaps. `nbreg` fits the mean-dispersion model only.

**Resampling, added 10 November 2026.** `sample` and `bsample` draw from the uniform stream in the order Stata's own programs do, so after the same `set seed` they keep the same observations in the same order; this is recorded for `sample #`, `sample #, count`, `bsample` and `bsample #`. The `bootstrap` and `jackknife` prefixes, with `_b` or a list of expressions, and `vce(bootstrap)` and `vce(jackknife)` on `regress`, print the tables Stata prints, and their variance matrices agree to 1 part in 10^9. That agreement depends on two things taken from Stata: the bootstrap sample is drawn as `bsample` draws it, and every replicate is kept in single precision, which changes the standard errors in about the seventh digit. `simulate` replaces the data with one observation per run, stored as `float`.

The warning `bootstrap` prints when a command sets no estimation sample, and its row of progress dots, are wrapped to the line size as Stata wraps them. `bsample` with `strata()`, `cluster()` or `weight()`, `sample` with `by()`, `bootstrap` with `strata()`, `cluster()` or `bca`, and `permute` are refused. Only `regress` takes `vce(bootstrap)` and `vce(jackknife)`; other estimators take the prefix, and print the model's title above the test of its coefficients without the rest of that estimator's own header.

**Further data commands.** `do`, `run` and `include` execute a do-file that is in the session's folder, with arguments as `1`, `2` and so on; `do` shows the file's output and `run` does not. `cross`, `joinby` (with `unmatched()`) and `stack` agree with Stata; `joinby` leaves the pairings of each observation in the order of the using data, where Stata's order within a group is arbitrary. `egen` gains `concat()`, `anycount()` and `cut()` with `group()`. `matrix list` accepts `e(b)` and `e(V)` directly.

**Tables, generalized linear models and time series, added 10 November 2026.** `table` with one row variable gives frequencies or one column per `statistic()`; with a row and a column variable it gives frequencies or one statistic. `proportion` reports logit-transformed confidence limits. `anova` takes factors, their interactions written with `#` and `##`, and `c.` covariates; its partial sums of squares, found by coding each factor as deviations and leaving one term out at a time, agree with Stata's, including main effects in the presence of an interaction. `glm` fits the Gaussian, binomial and Poisson families with the identity, logit, probit, complementary log-log and log links, and `cloglog` is also its own command; deviance, Pearson statistic, AIC and BIC agree with Stata's. `corrgram` reports autocorrelations, regression-based partial autocorrelations and the Q statistic, with Stata's character plot, and `ac` and `pac` draw them. `tssmooth ma` and `tssmooth exponential` agree with Stata, the exponential smoother being built in single precision step by step unless `double` is asked for. `collapse` takes weights: frequency weights repeat observations; analytic weights give the weighted mean and standard deviation, a sum equal to the weighted mean times the group's size, and unweighted counts; sampling weights give the weighted mean and the weighted sum.

`table` refuses layouts with parenthesised dimensions, more than two variables, several variables in one `statistic()`, a two-way table with more than one statistic, and the options that restyle a table. `anova` has no `repeated()` and prints no table of coefficients. `glm` takes the conventional (observed-information) standard errors only and has no `family(gamma)`, `nbinomial` or `igaussian`. `tssmooth` has only `ma` with equal weights and `exponential` with `parms()` given. `corrgram` and `tssmooth exponential` refuse a series with gaps.

**More instrumental-variable and time-series estimators, added 10 November 2026.** `ivregress liml` finds kappa as the smallest root of the determinantal equation and fits the k-class estimator; `ivregress gmm` is the two-step estimator with a robust or unadjusted weight matrix, and reports Hansen's J in `e(J)`. Both agree with Stata to 1 part in 10^9, and `ivregress` now accepts `if` and `in` after the instrument list. `prais` fits the Prais-Winsten and, with `corc`, the Cochrane-Orcutt regression, iterated or `twostep`, with both Durbin-Watson statistics; its total sum of squares is the variation of the transformed outcome about its mean, as Stata reports it. `dfuller` gives the Dickey-Fuller and augmented tests with a constant, with `trend` or with `noconstant`. Its critical values are Fuller's, interpolated by sample size as Stata interpolates them, and its p-value is MacKinnon's approximation; both sets of published constants are in `src/runtime/more-postestimation.js`. As in Stata, `if` and `in` select the observations of the test regression while lags reach back before them. `notes` and `numlabel` are added.

`ivregress liml` takes the conventional variance only; `ivregress gmm` has no `igmm` and no HAC or cluster weight matrix; `ivregress, small` is refused. `prais` and `dfuller` refuse panels and series with gaps; `dfuller` has no `drift` and no `regress` option.

**`margins` after the newer estimators, added 10 November 2026.** After `tobit`, `qreg`, `areg`, `newey` and `prais` the margin is of the linear prediction; after `nbreg` of the predicted count; after `glm` of the predicted mean under its link; after `cloglog` of the probability. Stata refers these to the t distribution after `tobit` and `areg` and to the normal after `qreg`, `newey` and `prais`, and the runtime does the same. After `ologit`, `oprobit` and `mlogit`, `margins` gives the probability of every outcome, or of one with `predict(outcome(#))`, and `dydx()` its derivative in a covariate, averaged over the sample or at the means with `atmeans`. Standard errors there use every parameter of the model, cut points included, and the gradient of each quantity in the parameters is found by differencing. Thirty recorded tables agree with Stata's to the tolerance used for the likelihood estimators.

After the ordered and multinomial models `margins` takes no `at()`, no factor list, and needs every regressor to be a plain variable. After `ivregress`, `xtreg` and `bootstrap` results `margins` is not available.

- `import delimited` and `export delimited` work on text files in the session's folder, which the Console fills from a file the student chooses. Installed Stata on the development machine cannot run `import delimited`, so these follow Stata's documentation and are covered by tests that state the expected behaviour, not by a native record. Two choices are this site's: variable names are lowercased unless `case(preserve)` is given, and a column of whole numbers too large for `long` is stored as `double`.
- In an interaction, a cell at a base level is left out when it adds nothing to the terms already in the model, which reproduces Stata's choices in the recorded cases (`##` with and without main effects, factor by continuous, factor by factor, a bare `g#h`). `##` takes any number of parts. `ib#.` and other base operators are refused. `ivregress` takes plain variables only. `xtreg, re` is refused when the between regression has no degrees of freedom left, where Stata switches to another estimator of the variance components.

Naming one stops the command with a message, so that no option is accepted and silently ignored. An option that is in neither list is refused as not allowed.

- `pctile, genp()` labels its variable `percentages`; Stata's label carries the name of a temporary variable. `cumul` without `equal` gives tied values consecutive proportions in data order, where Stata's order among ties is arbitrary. `fillin` leaves rows in a stable order within each cell.
- `summarize, detail` with analytic weights, `ci proportions`, `tabulate, exact` beyond 2 x 2, and `anova` are refused.
- `runiform()` uses the 64-bit Mersenne Twister and returns the same doubles as Stata after the same `set seed`, checked on recorded draws. `rnormal()`, `runiformint()`, `rbinomial()`, `rpoisson()`, `rbernoulli()` and `rexponential()` are built on it by this site's own methods: they are reproducible here and do not match Stata's draws.
- A number stored in a macro with 16 significant digits can differ from Stata's in the last digit, because Stata's conversion to decimal is not exactly rounded there.
- The cases use small invented datasets. They establish the stated behaviours on those cases and nothing about speed or about data with tens of thousands of observations.
- The Console runs the interpreter in a worker and falls back to the page when a worker cannot start. Stop ends the worker, which also discards the session's data. A do-file is stopped after 200,000 commands in either case.
